## Проектная работа по курсу Data Engineering## Система автоматической обработки хранения и прогнозирования данных о продажах сети супермаркетов
Курсовой проект по дисциплине Data Engineering. Реализация конвейера данных по методологии ELT Extract Load Transform на стеке Modern Data Stack MDS.
Проект развернут локально в изолированном контейнеризированном окружении под управлением операционной системы Linux Mint и реализует сквозной процесс от генерации сырых транзакций до построения аналитических витрин прогнозирования и инфраструктурного мониторинга.
------------------------------
## Архитектура системы и Стек технологий
Проект объединяет современные индустриальные инструменты обработки данных

* Оркестрация и Управление Apache Airflow 2.7.1 координирует расписание конвейера управляет зависимостями задач и перезапускает шаги при сбоях.
* Хранилище данных DWH PostgreSQL 15 Alpine реляционное хранилище логически разделенное на изолированные слои данных staging и analytics.
* Трансформация данных dbt Data Build Tool 1.7.3 отвечает за этап трансформации конвейера. Выполняет очистку типизацию денормализацию и сборку витрин.
* Бизнес аналитика BI Metabase слой визуализации ключевых показателей бизнеса построение интерактивных дашбордов для менеджмента.
* Прогнозирование ML компонент Python 3 psycopg2 binary математический модуль расчета трендов и прогнозных показателей продаж на 7 дней вперед.
* Инфраструктурный мониторинг Prometheus Grafana cAdvisor Node Exporter DevOps стек для контроля производительности контейнеров и хост системы в реальном времени.

## Структура Хранилища Данных## 1 Слой Staging staging raw_transactions
Сюда сбрасывается сырой поток чеков из супермаркетов в неизменном виде.

* transaction_id VARCHAR Уникальный идентификатор чека.
* timestamp TIMESTAMP Дата и время совершения покупки.
* store_id VARCHAR Идентификатор магазина Гипермаркет Супермаркет Мини маркет.
* product_id VARCHAR Идентификатор товара.
* quantity INT Количество позиций в чеке.
* price_per_item NUMERIC Розничная цена за единицу товара.
* total_amount NUMERIC Итоговая сумма по позиции.
* payment_method VARCHAR Способ оплаты Карта Наличные СБП.

## 2 Слой Analytics Справочники и Витрины dbt

* analytics dim_products Измерение товаров Имя категория закупочная себестоимость cost_price.
* analytics dim_stores Измерение магазинов Название город формат точки.
* analytics mart_daily_sales Витрина dbt Агрегированные исторические продажи. Рассчитывает общую выручку себестоимость и чистую маржу бизнеса net_profit.
* analytics fact_sales_forecast Витрина прогнозов Таблица с рассчитанными прогнозами выручки по категориям товаров на 7 дней вперед с учетом волатильности рынка.

## Детальный сквозной процесс обработки данных
Конвейер данных работает по методологии ELT. Это значит что данные сначала загружаются в DWH в сыром виде и только затем трансформируются внутри базы данных с помощью SQL что кардинально экономит ресурсы вычислительного хоста.
## Пошаговая цепочка выполнения
1 Генерация и инжест Скрипт generate_sales py Скрипт с помощью стандартных библиотек Python генерирует реалистичный массив транзакций чеков сети за прошедшие сутки. Учитываются коэффициенты веса дней недели в субботу и воскресенье объем продаж возрастает на 30 или 40 процентов. Происходит пакетная вставка Bulk Insert в таблицу staging raw_transactions.
2 Трансформация dbt dbt считывает сырые данные из staging производит очистку приведение типов фильтрацию дубликатов транзакций. Осуществляет операцию JOIN со справочниками продуктов и магазинов. На основе себестоимости товара и финальной цены продажи на лету рассчитывается маржинальность и чистая прибыль для каждой категории. Результат материализуется в физическую таблицу analytics mart_daily_sales.
3 Запуск ML модуля predict_sales py Скрипт прогнозирования подключается к уже готовой dbt витрине mart_daily_sales и извлекает из нее исторические агрегированные тренды продаж.
4 Формирование слоя прогнозов analytics fact_sales_forecast Математическая модель рассчитывает прогноз выручки на 7 дней вперед для каждой комбинации Магазин и Категория товара и записывает данные в финальную таблицу.
5 Потребление данных Metabase Grafana Metabase строит графики бизнес метрик на основе слоев mart и forecast. Grafana параллельно отображает утилизацию системных ресурсов в процессе выполнения всех этих шагов.

## Логика работы и модель ML компонента
В качестве алгоритма прогнозирования используется модифицированная модель скользящего среднего Moving Average с интеграцией фактора рыночной волатильности Stochastic Volatility Simulation.
## Как это устроено математически
1 Извлечение базового тренда Модель группирует исторические данные за доступный период и рассчитывает математическое ожидание среднее значение выручки для каждого магазина и категории товара отдельно по формуле
Base Trend = (Total Revenue 1 + Total Revenue 2 + ... + Total Revenue N) / N
2 Экстраполяция временного ряда Базовый тренд проецируется на временную шкалу вперед с шагом от 1 до 7 дней от текущей даты.
3 Симуляция стохастического шума Чтобы прогноз не выглядел линейным и статичным в модель внедрена функция генерации рыночных колебаний. Базовый тренд умножается на случайный коэффициент распределения в диапазоне от 0.93 до 1.07 с помощью алгоритма random uniform в Python по формуле
Predicted Revenue = Base Trend * Uniform(0.93, 1.07)
Это имитирует естественные колебания покупательского спроса в пределах 7 процентов и позволяет менеджменту сети супермаркетов закладывать вилку рисков при планировании поставок товара.
4 Запись данных UPSERT Данные пишутся в таблицу с использованием синтаксиса ON CONFLICT DO UPDATE. Это гарантирует что если пайплайн перезапустится внутри дня старый прогноз обновится актуальными данными а дубликаты строк не создадутся.

## Зоны ответственности систем контроля
Проект строго разделяет контроль над логикой данных и контроль над физической инфраструктурой.
## Что контролирует Apache Airflow Слой Оркестрации
Airflow отвечает за бизнес логику и последовательность шагов конвейера данных

* Расписание Запускает весь конвейер строго в заданный промежуток времени раз в сутки.
* Управление зависимостями Гарантирует что dbt трансформация не начнется до тех пор пока генератор данных полностью не запишет чеки в базу. В свою очередь ML модуль не запустится пока dbt не соберет для него свежую витрину. Если один из шагов упадет с ошибкой Airflow остановит конвейер и подсветит упавшую задачу красным цветом.
* Логирование Сохраняет все системные сообщения скриптов и команд dbt внутри интерфейса для быстрого аудита дата инженером.

## Что контролируют Prometheus и Grafana Слой Инфраструктуры
Этот DevOps стек работает обособленно и отвечает за техническое здоровье и стабильность железа

* Node Exporter Контролирует параметры вашей физической машины Linux Mint. Он следит за свободным местом на диске чтобы база данных Postgres не заблокировалась из за переполнения общей оперативной памятью системы и системной нагрузкой.
* cAdvisor Контролирует параметры изолированных Docker контейнеров. Он показывает сколько ресурсов процессора и памяти забирает планировщик Airflow во время работы dbt и нет ли перегрузки у контейнера Metabase BI при одновременном просмотре графиков несколькими пользователями.
* Grafana Агрегирует эти метрики из Prometheus и выводит их на красивый интерактивный DevOps экран дашборд номер 10619 сигнализируя о критических нагрузках на систему еще до того как они приведут к падению базы данных.

## Инструкция по локальному запуску
Весь проект полностью автоматизирован и поднимается одной командой.
## 1 Клонирование и запуск основного стека
выполните в терминале команды
cd supermarket_data_driven_dwh
docker compose up -d
## 2 Запуск компонентов мониторинга
Для изоляции от системных портов Linux Mint агенты мониторинга и Grafana запускаются прямыми командами в общую сеть
Запуск Node Exporter сбор метрик железа
./start.sh
Запуск cAdvisor сбор метрик контейнеров Docker
docker run -d --name monitor_cadvisor --network supermarket_dwh_project_default --network-alias cadvisor -p 8082:8080 --volume=/:/rootfs:ro --volume=/var/run:/var/run:ro --volume=/sys:/sys:ro --volume=/var/lib/docker/:/var/lib/docker:ro --volume=/sys/fs/cgroup:/sys/fs/cgroup:ro --privileged --device=/dev/kmsg gcr.io/cadvisor/cadvisor:v0.49.1
Запуск Grafana Визуализация метрик
docker run -d --name monitor_grafana --network supermarket_dwh_project_default -p 8085:3000 -e GF_SECURITY_ADMIN_USER=admin -e GF_SECURITY_ADMIN_PASSWORD=admin -v /home/auger/supermarket_dwh_project/grafana/provisioning:/etc/grafana/provisioning grafana/grafana:latest
